# Ansible Post-Provisioning

Terraform + ParallelCluster provision the infrastructure and base HPC cluster. **Ansible** is used after provisioning to configure software, services, and environment settings.

---

## When to Use Ansible

Use Ansible for tasks that are:

- **OS configuration** (packages, users, hardening)
- **Spack bootstrap** and module refresh
- **Lmod modulepath configuration**
- **Agent setup** (Wazuh, Node Exporter, Slurm Exporter, DCGM Exporter)
- **Custom scripts** shared across nodes

---

## Integration Options

### 1) ParallelCluster CustomActions
Run Ansible from the head node during post-install:

- Upload the playbooks to the head node
- Execute `ansible-playbook` as part of `CustomActions` in the ParallelCluster config

### 2) CI/CD After Terraform Apply
Run Ansible from a CI runner or a secure admin host once the cluster is up.

### 3) Manual Execution
From a trusted workstation:

```bash
ansible-playbook -i ansible/inventory/example.ini ansible/playbooks/site.yml
```

---

## Lmod Notes (Official Setup)

Lmod modulefiles are generated by Spack. The Ansible role **only** ensures that `MODULEPATH` includes the Spack module root so module discovery works consistently across head and compute nodes.

Recommended Spack module path (typical):

```
/opt/spack/share/spack/modules
```

If your Spack install path differs, adjust `spack_module_root` in [ansible/playbooks/site.yml](../ansible/playbooks/site.yml).

---

## Example Role: Lmod Modulepath

The `lmod` role:

- ensures `/etc/profile.d/lmod.sh` exists
- appends Spack’s module root to `MODULEPATH`
- sources that script from `/etc/profile`
